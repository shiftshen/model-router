# 智能执行任务（本机）

在 Mac 应用的模型库点击「智能执行任务」，填写任务、难度、能力类别和答案必须包含的短语，再点击「执行并验收」。结果会展示选中的路线、实际网关路线、每次调用的 request ID、上游报告的模型名、耗时、验收结果和答案。此入口是独立任务，不改变已有 Codex 对话或手选模型。

也可从命令行提交。先启动 Model Router 网关，再在仓库运行：

```sh
printf '%s\n' '{"text":"只回答 6×7 的结果。","complexity":"simple","category":"backend","acceptance":{"type":"exact_text","expected":"42"}}' | node src/product-cli.mjs run-task
```

自动执行要求当前路线有凭据或本地服务、24 小时内的连接检查、72 小时内的真实六项能力验证、当前端点/模型/协议/凭据版本匹配、该任务类别至少 80 分、足够的已证明上下文及输出预算。复杂任务还需综合至少 80 分；简单任务需至少 60 分。短题形式的 `long_context` 验证没有实际发送长输入，因此长上下文任务暂不自动执行。余额无法由连接成功证明；检测到额度耗尽会停止，直到后续成功记录恢复。没有合格候选时拒绝执行。

简单任务按类别成绩选合格路线；复杂任务把**结构化画像与合格候选快照**交给 Laya Typed-Decisions 主路由，必要时由 Jev 兜底。引擎看不到任务原文。任务原文仅发送给被选中路线的网关请求。选中 ID 必须在本次快照内。网关在任务模式下关闭其普通备用切换；验收失败后，执行器最多再尝试两个同样合格的候选。只有最终答案满足明确验收规则且网关路线日志确认一次完成，任务才算通过。可用验收规则：`exact_text`、`contains_all`、`json_subset`；Mac 界面提供短语检查。

本机审计文件为 `~/.codex/model-assistant/task-runs/<task-id>.json`，网关调用记录为 `~/.codex/model-assistant/route-log.json`。两者可按 task ID 与 request ID 对照；任务审计不写 Key、完整原文或答案。网关返回的模型名是上游报告值，并不能独立证明内部权重身份；Codex 子智能体的 `model` 参数也不是供应商调用证据。

现有 GPT-5.6 验证文件只作历史证据，新自动分配排除全部 GPT-5.6 路线。本机未配置且未验证 `gpt-6-sol` 的可用执行路线时不会假定它合格。本机 `qwen3-vl:latest` 是 8.8B；一次真实六项验证综合 65 分，仅在通过对应类别、简单任务且输出预算至少 700 时考虑。Bonsai 27B 的历史 59 分不能作为通用默认资格。
